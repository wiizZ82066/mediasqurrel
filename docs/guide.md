# Media Squirrel

> [返回项目首页](../README.md) · 使用、数据维护与开发完整说明。

本机运行的微博、抖音内容下载与相册管理工具。后端使用 Python + FastAPI，前端使用 Vue 3 + Vite，默认由 Playwright 访问平台；媒体原件保留为文件，SQLite 保存任务、订阅和媒体索引。

当前主要运行方式是 `python run.py`。Electron、PyInstaller、NSIS、安装包发布、签名和桌面自动更新暂不作为本轮开发目标；旧代码与 `electron/tests` 中有效的通用回归测试仍保留。历史安装包不一定包含当前 `main` 的功能，相同版本号也不代表相同代码。

## 能力与边界

- **下载**：微博正文、图片与 Live 图；抖音视频、图集、官方封面与正文。支持队列、取消、真实计数与传输进度、完成摘要和媒体库定位；下载结果展示封面、作者和时间，正文在媒体库查看。下载完成后若媒体库仍在建立索引，预览会自动等待同步完成，无需手动重试。点击空输入框或“粘贴”可读取剪贴板并识别平台，已有输入不会被覆盖；也可使用 Ctrl+V。
- **任务**：任务摘要与日志持久保存，分页筛选、搜索、按需加载日志、重试关联原任务。隐藏任务记录可以恢复，不会删除日志或媒体；删除详细日志是另一项需要确认的操作。
- **媒体库**：作者与时间线视图，连续滚动、日期导航、平台和媒体类型筛选、正文搜索；搜索筛选可展开或收起，Live 图封面和查看器支持鼠标悬停静音播放，触屏或键盘可使用播放按钮；图片、视频和 Live 图使用同一查看器，支持键盘导航与返回原位置。缩略图和封面分析在受控后台队列执行，人脸位置只辅助本地封面裁切，不修改原图或建立身份分类。
- **订阅**：博主搜索、手动添加、独立的间隔与固定时间计划、手动扫描、头像缓存和扫描记录。选中搜索结果后仍需点击“添加订阅”。订阅卡片显示昵称，不展示博主 UID；标识仍用于搜索、扫描与去重。
- **设置**：运行参数、分级环境检测、独立下载检测、媒体索引、复制迁移、备份恢复和脱敏诊断。

性能取决于媒体规模、磁盘、图像尺寸和缓存状态；分页与后台处理不意味着任意规模都能瞬间打开。平台登录、限流、页面变化和内容可见性会影响采集结果，增加扫描计划不能保证永不漏抓。

抖音支持视频和图集，包括 `/video/`、`/note/`、`/slides/` 作品链接及跳转到这些页面的短链。图集读取与作品 ID 匹配的详情接口或公开页面数据，按平台顺序保存到 `photo/img0001.*`；以图片实际字节校验 JPEG、PNG、WebP 或 GIF 格式，不把所有图片伪装成 JPG。一张图失败也不会标记整条成功，备用地址和重试继续使用同一存档；视频仍保存原有视频文件和官方封面。

下载完成后优先索引该作品的实际目录，保留任务“同步媒体库”状态和自动定位。定点索引与全根扫描串行，不会误标其他条目缺失；若全根扫描正在进行，会先等待它完成。手动更新索引和原有启动扫描仍保留，未增加周期扫描定时器。

## 可选的抖音接口试点

设置页可选择“浏览器解析”或已配置的实验性接口解析。默认仍为浏览器，收到有效详情就返回，不再额外固定等待六秒。该接口试点目前仅支持 Windows；通过单独安装的 Catbus CLI 只读取作品详情，下载、正文、封面、清单与索引仍由本项目处理，订阅扫描没有切换通道。

本项目不附带或自动安装 Catbus，不复制其签名代码，也不自动导入本项目 Cookie。单独准备兼容版本后，在启动服务前设置三个绝对路径环境变量：`MS_DOUYIN_ADAPTER_NODE`（Node 可执行文件）、`MS_DOUYIN_ADAPTER_ENTRY`（Catbus 包公开的 JS 命令入口）、`MS_DOUYIN_ADAPTER_HOME`（独立的 Catbus 数据目录）。运行环境检查只读取公开包信息并执行 `node --version`，不验证登录。当前适配基于 [Catbus e637cb4](https://github.com/cv-cat/catbus/tree/e637cb43078cbe776313ac3500cf0646c2a7b843)，其 Node 范围为 `^22.22.2 || ^24.15.0 || >=26.0.0`；本机原有 Node 24.13 不满足，未自动升级。

Catbus 会管理和刷新自己的登录信息，缺 UIFID 时可能补请求一次；本项目不会在登录失效、风控、限流或未知响应后重试并轮换通道。只有本地适配器不可用或明确不支持时，才提示并使用一次浏览器解析。外围错误及原始响应不会写入任务日志。命令输出、超时和子进程清理均有限制，协议回归使用合成数据。接口通道尚未做同批真实作品的速度和完整性对比，不能据此宣称提速。

未将第三方整包合入项目；Catbus 的 LICENSE 与 README 使用限制存在不同表述，直接复制分发前仍需澄清。当前实现是独立的可选命令桥接。

## 首次安装与启动（Windows PowerShell）

当前开发验证环境为 **Python 3.14.2、Node.js 24.13、Vite 6.4.3**。这不是所有 Python、Node 或操作系统版本的兼容矩阵。锁定的 Vite 声明 Node `^18.0.0 || ^20.0.0 || >=22.0.0`，但依赖自身可能有更窄限制，不能据此认为这些版本均已验证。

先安装 Python、Node.js 和 Git，再执行：

```powershell
git clone https://github.com/wiizZ82066/mediasqurrel.git
Set-Location mediasqurrel
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
Set-Location frontend
npm ci
Set-Location ..
.\.venv\Scripts\python.exe run.py
```

使用已激活的虚拟环境时，启动命令就是 `python run.py`。微博下载器使用 Playwright Chromium；抖音浏览器逻辑优先尝试系统 Chrome，并提供 Chromium 回退。设置页可分别检测两种浏览器是否实际可启动。浏览器文件存在不等于已通过启动检测，更不等于平台下载可用。

Windows 也可双击项目内的 `start.bat`。它会固定从自身目录启动，优先使用项目的 `.venv`，否则使用 `PATH` 中的 Python；默认转入 `pythonw.exe` 隐藏后台运行，启动用的命令行窗口会自动关闭。`python run.py` 或 `start.bat --console` 保留控制台，适合排错；`--no-tray`、`--reload` 也保留控制台。缺少 Python 等启动前错误会保留窗口；隐藏运行后的错误会弹出原因和启动日志位置。

首次启动会构建前端。以后启动会检查 `frontend/src`、`public`、构建配置和锁文件的指纹，以及构建资源完整性；只有源码变化或产物缺失、损坏时才运行 `npm run build`，不会每次安装依赖或无条件重建。拉取代码后，若 Python 依赖或前端锁文件变化，请分别重新安装对应依赖；启动器不会代办安装。

默认打开 `http://127.0.0.1:8642`，服务只绑定本机回环地址。常用选项：

```powershell
python run.py --no-tray       # 不使用托盘，在控制台运行
python run.py --no-browser    # 不自动打开网页
python run.py --port 9000     # 使用另一个本机端口
python run.py --background    # Windows 隐藏控制台，在托盘后台运行
```

关闭浏览器后，服务、排队下载和订阅扫描仍可继续。退出请使用托盘菜单或控制台 Ctrl+C，程序会停止调度并清理工作子进程。重复启动只有在数据目录、源码位置和启动时的代码指纹均匹配，且前端构建有效时才打开现有实例；检测到旧代码或无法核实的旧实例会提示先从托盘正常退出再重新启动。更新代码后，关闭网页不能代替退出后台服务；服务重新启动后，已打开的网页也需要完整刷新，切换栏目不会重新加载前端代码。同一数据目录不能有两个写入进程。端口被其他程序占用时会提示，不会杀掉占用进程。

多个启动入口同时执行时，会在前端构建和服务初始化之前协调：后来的启动等待已有服务就绪并核验身份，不会重复构建或启动第二个后端。等待上限为 4 分钟；超时会提示检查日志和托盘，不会结束原进程。启动进程异常退出后，系统会释放锁，下一次启动可以重试，无需手动删除锁文件。

托盘显示下载、排队和扫描数量，可打开网页、媒体目录、数据目录及日志目录。退出时若有未完成工作，会先提示；确认后保留“正在退出”状态，直到后台停止调度并清理子进程。隐藏模式若无法创建托盘，会正常关闭服务并提示错误，不会遗留没有退出入口的后台服务。

设置页提供“开机自启动”，默认关闭。开启后在当前用户的 Windows 启动文件夹创建 `Media Squirrel.lnk`，固定 Python、源码位置和工作目录，不需要管理员权限。其含义是**当前用户登录后**后台启动托盘，不自动打开网页，不在登录前运行，也不会唤醒电脑；Windows 可延迟执行或在系统“启动应用”中禁用。保存时回读核验，失败会尝试恢复原登记；旧版 `HKCU Run` 入口在新快捷方式验证成功后移除，避免重复启动。读取状态不会自动修改系统设置。依据：[Microsoft 启动应用说明](https://support.microsoft.com/en-gb/windows/experience/startup-boot/configure-startup-applications-in-windows)。

移动源码或 Python 环境后，点击“检查启动状态”，再用“重新登记”更新入口；临时数据路径环境变量仍会阻止启用，避免登录后使用另一份数据。自启动入口和托盘就绪情况记录在启动日志中，登记成功不等于已经通过下一次真实登录验证。有任务时从托盘退出会独立弹出确认框：选“否”继续运行，选“是”请求正常停止并清理子进程；等待确认期间不阻塞托盘消息处理。

隐藏模式的运行和启动诊断在数据目录 `logs/startup/` 中脱敏保存；每次运行最多约 3 MiB，保留最近 5 次，正在被进程占用的旧日志会延后清理。数据目录不可写时尝试系统临时目录，并在错误提示中显示位置。这是独立的启动诊断限额，不改变任务和详细下载日志的永久保留策略。

日常通知只在打开的网页内显示，关闭网页后没有系统通知；启动失败提示属于启动错误对话框。应用退出、电脑关机或休眠期间不能执行扫描，恢复运行后沿用合并补扫规则，没有配置系统计划任务或唤醒电脑。

## 数据位置

新源码安装默认使用：

| 内容 | Windows 默认位置 |
| --- | --- |
| 数据库、任务日志、设置与本地登录信息 | `%LOCALAPPDATA%\Media Squirrel\data` |
| 媒体原文件 | `%LOCALAPPDATA%\Media Squirrel\library` |
| 此源码副本的本地路径配置 | 项目中的 `.mediasquirrel.local.json`（Git 忽略） |

媒体文件应放在项目目录之外。设置页显示实际生效位置，以及发现的旧源码版、旧桌面版候选位置；不会自动导入、合并或搬走旧数据。旧桌面版常使用 `app_data`，旧源码版还可能把媒体存到项目目录，不能把换启动方式视为迁移完成。

首次使用、尚未产生数据时，可在启动前创建本地路径配置，填写独立的绝对路径，例如：

```json
{
  "data_dir": "D:\\MediaSquirrelData\\data",
  "library_root": "D:\\MediaSquirrelData\\library"
}
```

已有数据后，请通过设置中的预检与副本流程更换位置，避免只改路径导致旧数据看似消失。高级环境配置包括 `MS_HOME`（基础目录）、`MS_APP_DATA_DIR`（应用数据）、`MS_LIBRARY_DIR`（媒体）、`MS_PATHS_FILE`（本地路径配置文件）和 `MS_PORT`。旧的 `MS_DATA_DIR` 表示包含 `app_data/` 与 `library/` 的便携根目录，并非数据库目录；路径环境变量覆盖本地配置时，界面路径切换会要求先移除覆盖并重启。

媒体原件、`context.md` 和新存档的 `entry.json` 是应保留的源数据；订阅、任务历史、日志与设置也应备份。媒体查询索引、缩略图和封面分析缓存可以重建。新存档目录包含日期、平台和内容 ID；`entry.json` 记录稳定 ID、文件清单和完成状态。旧的 `<作者>/<日期>/`、`context.md`、图片与 Live 图配对仍可建立索引，旧格式会单独标记，不能仅凭一个 `context.md` 推断历史下载完整。新的纯文字微博可以是有效完成存档。

## 四类数据维护

设置中的操作会先生成预检结果，展示源与目标、文件数量、容量、冲突和缺失，再由用户确认执行。

| 场景 | 当前行为 |
| --- | --- |
| **A. 数据库结构升级** | 当前数据库启动时按版本升级，升级前创建一致性备份，迁移使用事务并记录版本。引入旧版数据库可选“旧数据库结构升级副本”，在新目录中升级，不覆盖旧库、不合并两份业务历史。 |
| **B. 已有媒体建立索引** | 只读取已有媒体，在应用数据库中登记媒体根与索引；不复制、移动或改写原媒体。当前配置的默认媒体根会在后台增量扫描；其他旧位置需明确选择。 |
| **C. 换磁盘或媒体位置** | 复制到新目录并校验文件，原目录保留；完成后另行确认下次启动路径。当前进程不会直接换库，退出重启后再次验证并应用映射。 |
| **D. 备份与恢复** | 备份数据库、详细日志和设置；恢复到新的数据目录并验证，再明确选择下次启动使用。媒体原件需另行复制，备份不包含 Cookie、浏览器档案和缓存。 |

维护进度与计划持久保存，可以取消并在条件仍满足时继续。源数据变化、目标冲突、文件缺失或空间不足会要求处理或重新预检，不会删除原目录或覆盖旧数据库。准备副本后若又产生任务、日志、订阅或设置变化，路径切换会拒绝使用过期副本；应重新准备，再及时退出重启。

跨电脑迁移时，需要分别携带应用数据备份和媒体副本，在新电脑恢复并重新建立或确认媒体路径。凭据不会随备份迁移，登录需重新完成。备份仍可能包含私人正文、历史与路径，不能当成可公开分享的诊断包。

## 任务、日志与媒体浏览

任务和详细日志默认永久保留，不按天数或条数自动过期。日志分批写入 SQLite，终态日志压缩归档，页面只按需读取有界窗口。异常断电可能丢失最后尚未提交的一小批日志；排队任务重启后继续调度，原运行任务标记“中断”，可创建关联原任务的重试，不承诺字节级断点续传。

设置页展示任务数量、数据库和归档日志占用、数据盘剩余容量，统计最多缓存 60 秒。低于 512 MiB 会提醒备份或手动清理，不自动删除历史。缩略图使用容量目标与淘汰机制，最近 10 分钟使用的缓存受保护，可能短时超过设置的目标。

媒体时间线优先使用 `context.md` 的发布时间，其次为目录日期、新存档记录的下载时间，均缺失时使用导入时间；界面显示日期来源，日期分组按 Asia/Shanghai。没有默认从 EXIF 推断拍摄日期。列表与正文搜索走持久化索引，原文件变更后通过增量扫描校正。删除文件不会自动删除任务记录，也不会让已确认下载成功的订阅内容自动重下。

封面左下角用图标区分视频和 Live 图，悬停可查看类型与数量。正文保留 Unicode Emoji、换行和原文；已收录的微博 `[表情名称]` 使用官方对应图形，首次显示时由本机服务向固定的官方静态地址请求，随后使用本地缓存，无需登录。请求不携带 Cookie，浏览器不直接连接表情 CDN；未收录或加载失败时显示原始代码。新下载会保留 HTML 图片表情的文字描述，旧存档中已经丢失的文字无法凭索引重建恢复。

媒体库采用连续滚动加载，不再显示页码；接口按游标分批返回摘要，界面仅渲染可视区域附近的卡片。媒体库按可用宽度自适应列数，大屏不限制为三列，单次读取量也随窗口高度调整并保留上限。右侧独立作者栏可直接切换并独立滚动，支持收起以扩大媒体区，同一页面会话内保留折叠状态；窄屏可展开选择，搜索与其他筛选仍可折叠。返回媒体库保留已加载内容和滚动位置，需要查看最新索引结果时点击“刷新内容”。任务卡片操作区的“打开文件夹”和媒体卡片右下角的文件夹按钮可直接打开内容目录。任务卡片隐藏链接、日期及输出路径行，保留状态、关键结果与详细日志入口。查看器还可在 Windows 文件资源管理器中选中当前文件，或从“打开”菜单选择默认应用、系统“选择打开方式”；Live 图打开配对视频。系统选择窗口仅用于本次打开，不主动修改默认关联。

设置中的默认视频音量为 50%，可保存为 0–100%；新打开的视频按该值播放，单次播放器调节不覆盖默认设置。Live 图的鼠标悬停预览保持静音。

## 订阅计划与扫描覆盖

新增订阅首次扫描只建立基线，不自动回溯下载全部历史。间隔计划、每天一个或多个时点、按星期、明确日期、按天／周／月重复可以分别设置；计划包含时区、开始日期、次数或结束日期，并显示下次执行及结果。按月重复沿用起始日，短月份夹到月末；次数计算计划时点，包含错过后被合并的时点。

添加或编辑订阅时可设置下载标签，留空下载全部新内容。匹配微博正文、抖音文案中的完整 `#标签`、`#标签#` 以及平台话题元数据，命中任一标签即可；最多 20 个标签，每个不超过 80 字，统一全角/半角和英文字母大小写，不以部分词语当作命中。显示标题仍为摘要，判断不截断到前 60 字。只保存匹配用的话题、规则与决定，不把完整正文写入任务日志。

博主名字旁显示“扫描中”；本轮发现的内容通过下载完整性验证后显示“有新内容”，仅入队、失败或无更新时不显示该标签。下一轮扫描重新计算，标签状态在刷新或重启后保留。旧任务没有扫描关联时不推测为新内容，从升级后的新扫描开始记录。

下载标签折叠面板可回查发现、过滤、待完整正文、入队与下载结果。微博长文在未命中且列表正文不完整时尝试补读长文，每轮最多 10 条，和列表扫描共用时间预算；失败时保留待判断状态，后续扫描会继续尝试，包括已经离开回溯列表的待判断内容。平台拒绝长文访问时仍可能无法确认标签，不会误标下载成功。规则变更影响新发现内容及失败下载的自动重试，入队前会再次检查最新规则；不会取消已入队任务，也不会自动补下载以前过滤掉的内容。首次基线、已下载去重和直接手动下载不变。

手动扫描不推迟原计划；同一订阅的重叠触发共用扫描与去重。休眠或停机错过的到期触发会在应用恢复运行后合并补扫，不逐个重放。失败有有限退避重试，扫描结果与下载结果分别记录；发现、入队、下载成功、失败待重试不会混成一个“已见”标记。用户取消的下载不默认自动重试。

微博先从主页资料读取昵称、头像及作品列表入口，再主动分页；访客权限不足时明确提示登录，不把受限响应当成空内容。订阅页可主动打开微博或抖音登录窗口，凭据仅保存在当前数据目录，本地存在不等于平台仍接受。

扫描支持受限分页与重叠回看窗口，可设置最大页数、条目数、超时和回看范围。界面记录覆盖不足及原因；平台限流、置顶内容、页面变化、未公开内容或超过扫描上限仍可能造成遗漏。应结合扫描记录判断覆盖情况，必要时使用明确链接下载。

## 检测与排错

设置页按不同证据分别展示结果：

1. **依赖与脚本**：实际导入依赖及下载脚本、解析脚本语法，并检查浏览器文件；不只看入口文件是否存在。
2. **浏览器环境**：尝试启动浏览器并打开空白页，不访问平台。
3. **登录态**：显示本地是否保存登录信息；保存存在不代表平台仍接受，登录内容不会展示在界面。
4. **真实下载**：填写自己确认的测试链接，再确认联网；输出进入独立诊断目录，不加入正常媒体库。从任务详情查看实际结果。

端口冲突可先检查已有实例，或使用 `--port`。构建提示缺少依赖时，在 `frontend` 执行 `npm ci`。平台验证或登录失败时，按页面提示完成验证，并检查对应任务或扫描记录，不应把重试视为必然恢复。脱敏诊断导出用于排错，分享前仍应自行审阅。

## 开发与扩展

生产式源码运行由 FastAPI 托管前端构建。开发时可在两个终端分别运行：

```powershell
# 终端一，项目根目录，使用已准备的 Python 环境
$env:MS_DEV = '1'
python run.py --reload --no-tray --no-browser

# 终端二
Set-Location frontend
npm run dev
```

开发页面为 `http://127.0.0.1:5173`；如更换后端端口，两个终端应使用相同的 `MS_PORT`。结束开发后移除 `MS_DEV`，恢复正常前端构建检查。

主要模块：`app/task_manager.py`、`task_store.py` 管理任务与日志，`catalog.py`、`library_service.py` 管理媒体索引，`watcher.py`、`scheduling.py` 和 `scanners/` 管理订阅，`maintenance.py`、`path_transition.py` 管理数据维护。前端设计见 [DESIGN.md](../DESIGN.md)。

下载脚本由 `scripts_manifest/*.json` 注册。扩展时需同时适配参数校验、进度协议、`entry.json` 完成标记、媒体索引及平台界面，并添加有价值的回归测试；并非添加清单就能保证所有能力自动接入。新增代码文件只在白名单 `.gitignore` 中放行明确路径，不放开媒体目录。

提交前运行 `python .github/scripts/check-repository.py` 并人工审查差异。个人媒体、本地报告、数据库、缓存、浏览器档案、Cookie、密钥和私人路径不得进入 Git。测试使用隔离目录，不能把真实平台测试、受控测试和静态检查混称为同一种验证。

常规 CI 在 Windows 与 Linux 上运行 Python 3.12 后端回归，在 Node 22 下执行前端测试和构建；不安装 Electron 或触发打包发布。本地可运行以下检查：

```powershell
python .github/scripts/run-tests.py --suite business
python .github/scripts/run-tests.py --suite legacy
npm --prefix frontend test
node --test electron/tests/updates.test.cjs
npm --prefix frontend run build
```

Python 测试入口在导入应用前切换到临时数据目录，并阻止测试主进程访问外网；允许回环地址以验证本地接口。它不读取实际账号或证明真实平台当前可用，也不能替代浏览器实测和真实链接验收。平台清单的能力声明仅表示已实现的功能，不代表登录、网络或运行环境已就绪。

## 抖音直播与弹幕

在抖音订阅卡片展开 **直播录制**，默认跟随这位博主，从正常主页响应识别直播状态与入口，无需填写直播间链接。也可切换到指定完整地址 `https://live.douyin.com/房间号`；旧配置仍保留原链接方式。勾选自动录制并保存后生效，所有订阅默认关闭。主页身份和直播间归属必须匹配订阅身份；未知状态或平台验证不会误判为下播。作品扫描开关、时间计划及下载标签与录播独立。

- 默认每分钟检查，可点选秒、分钟、小时、天，范围为 1 分钟至 24 小时。可同时设置一个固定时间计划：每天、按星期、多个指定日期或周期重复，每天最多 24 个时间点。时间通过小时/分钟下拉框选择，星期通过按钮切换，日期通过日历添加；作品扫描计划使用同样的控件。两个调度依据分别保留，手动检查不推迟计划；错过多个时点后合并检查一次，只检查当时状态，不能补录过去直播。仅固定时间检查可能错过两个时点之间的短直播。
- 录制期间每分钟确认当前直播间状态；最多同时检查 2 位博主、录制 2 路直播。网络失败逐步延长间隔，平台限流后等待 30 分钟；立即检查至少间隔 30 秒。固定计划耗尽后停止定时检查，仍可手动检查。
- 录播状态放在博主名字旁边，每 5 秒刷新：关闭时显示“未开启录播”，开启后区分未开播、已开播、连接、录制、保存及状态待确认。点击状态可展开详情，查看实际视频时长、大小与弹幕数。视频超过 25 秒未推进时提示暂未更新，超过 60 秒会停止卡住的收流并重新检查。作品扫描完成计数、扫描计划和下载标签放在二级详情中。
- 启动直播连接遇到网络或服务器临时故障时最多额外尝试 2 次；仍失败则保留本次记录，60 秒后重新检查并获取新地址，连续失败逐步延长至最多 15 分钟。403、404、429、无效视频和磁盘写入问题使用固定的安全错误说明，不记录签名地址或请求凭据；平台限流仍等待 30 分钟。录制失败不会统一误报为入库失败。
- 按收到的直播流保存一个 MP4，不做定时分段。下播或点击 **停止并保存** 后校验可播放性并入库；手动停止同时关闭该博主的自动录播。视频标题、来源、录制开始时间与结束原因写入 `context.md`。开始录制时间不等于真实开播时间，也不能补回启动前已错过的直播。
- 结束后的录播同时出现在 **任务记录**，显示正常下播、手动停止或异常中断，以及视频时长、大小、弹幕数量和结果日志。可从任务打开对应媒体库内容、文件夹或直播录制详情。启动时补齐已有录播的任务摘要，已隐藏的记录仍保持隐藏；录播不会进入下载队列，也不能通过“创建重试任务”重放已结束的直播。
- 同一订阅、相同平台直播编号的已保存分段归入 **录播合集**，跨午夜也可归组；不同直播编号不会仅因时间接近而自动归组。媒体库和任务列表展示合集，可展开每次成功／失败记录。播放完一段自动进入下一原片，也可点选分段；文件夹与“打开”操作指向当前分段。已有每日合并副本保留在磁盘与历史记录中，默认改为浏览原片合集，不再自动拼接或转码。
- 每段弹幕保留文字、Emoji、实际接收时间和本段的 `video_time_ms`，不重排成连续总时间轴。每段 `chat.meta.json`、`chat.events.jsonl` 与原视频保留，合集关联保存在数据库中，备份时应一起保留数据库和媒体。查看器显示各段开始、收尾完成时间及段间间隔；收尾完成不等于最后画面时间，也不代表整场完整。缺失文件明确标注，未录到的画面和弹幕不补造；后续处理训练数据时需要尊重分段、采集缺口与未对齐标记。
- 录播记录中的 **将开播时间加入检查计划** 会把平台提供的开播时间填入现有固定时间计划，去重且保留原有时间点；可调整后保存。平台未提供或历史未保存该时间时，按钮明确改用“录制时间”，不将其冒充真实开播时间。
- 间隔与指定时间统一放在折叠的 **检查计划** 中操作，展开后可单选或同时使用，原有设置不变。作品扫描也通过统一的 **扫描计划** 子菜单管理；从录播时间添加计划会自动展开编辑区。
- 画质可选最高可用（默认）、原画、超清、高清、标清、流畅。指定档位不可用时只向更低档位回退，无对应流时报告错误；实际档位写入录播记录和 `context.md`。分辨率、帧率、编码及音频沿用直播源，不额外转码，档位名称不等于固定分辨率。
- 新录制的 `chat.jsonl`（schema 2）只保留 UTF-8 文字、Emoji 和时间信息，不保存发送者 ID、昵称或消息 ID。`video_time_ms` 基于收到消息时 FFmpeg 的输出进度估算视频播放位置，尚无进度时为 `null`；`recording_elapsed_ms` 是从录制请求开始计时，`received_at` 与 `platform_created_at` 为 UTC 时间；平台未提供发送时间时后者为 `null`，不伪造时间。视频进度停滞时最多外推 2 秒，避免把断流等待时间误当视频内容。网络与直播缓冲仍会产生偏差，不承诺逐帧同步。
- 采集摘要写入 `chat.meta.json`，连接变化、缺口和周期性视频进度对齐点另存 `chat.events.jsonl`。仅采集网页连接推送的文字聊天，不包含礼物、点赞或私信。旧 schema 1 文件保持原样，不静默删除已有字段。
- 弹幕采用独立浏览器会话，复用本机已保存的登录态；浏览器自动处理平台连接，采集器不会发言。最多缓存 16 帧，每帧 512 KiB；解压上限 4 MiB，最近 10000 个消息 ID 去重，约每 2 秒刷新并同步文件。拥塞、格式变化、断线和写入失败会标明；平台未推送的消息无法补齐，采集结束不代表全场弹幕完整。
- 视频与弹幕长期保留，不自动删除。数据库保存监控配置与每次录制记录，不存直播流签名地址或 Cookie。原文件继续按作者/录制目录保存，弹幕作为配套源数据参与媒体目录复制；数据库备份不会包含视频或弹幕。
- 剩余空间不足 2 GiB 时停止并关闭该博主自动录播。断流、退出程序或异常重启后的残留文件标记中断；可播放部分入库，不可播放的 `.part` 文件仍保留。重试生成新文件并关联同场上一记录，不覆盖旧片段、不承诺断点续录。入库失败可从录播记录重试。
- 关闭网页后继续后台监控；完全退出程序会停止录播并收尾，下次运行重新检查。子进程通过父进程管道关闭信号停止收流。数据维护与正在录制/检查/入库互斥，托盘状态和退出确认包含录播数量。

录播组件通过 `requirements.txt` 中的 `imageio-ffmpeg==0.6.0` 提供；设置页的依赖诊断会实际启动 FFmpeg。平台联网、长时稳定性与不同直播编码仍需分别验证。弹幕数据只做采集和保留，本轮不做模型训练或人脸身份匹配。
