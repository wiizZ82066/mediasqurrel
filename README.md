# Media Squirrel

本机运行的微博、抖音内容下载与相册管理工具。后端使用 Python + FastAPI，前端使用 Vue 3 + Vite，Playwright 负责平台访问；媒体原件保留为文件，SQLite 保存任务、订阅和媒体索引。

当前主要运行方式是 `python run.py`。Electron、PyInstaller、NSIS、安装包发布、签名和桌面自动更新暂不作为本轮开发目标；旧代码与 `electron/tests` 中有效的通用回归测试仍保留。历史安装包不一定包含当前 `main` 的功能，相同版本号也不代表相同代码。

## 能力与边界

- **下载**：微博正文、图片与 Live 图；抖音视频、官方封面与正文。支持队列、取消、真实计数与传输进度、完成摘要和媒体库定位。下载完成后若媒体库仍在建立索引，预览会自动等待同步完成，无需手动重试。点击空输入框或“粘贴”可读取剪贴板并识别平台，已有输入不会被覆盖；也可使用 Ctrl+V。
- **任务**：任务摘要与日志持久保存，分页筛选、搜索、按需加载日志、重试关联原任务。隐藏任务记录可以恢复，不会删除日志或媒体；删除详细日志是另一项需要确认的操作。
- **媒体库**：作者与时间线视图，分页、日期导航、平台和媒体类型筛选、正文搜索；搜索筛选可展开或收起，Live 图封面和查看器支持鼠标悬停静音播放，触屏或键盘可使用播放按钮；图片、视频和 Live 图使用同一查看器，支持键盘导航与返回原位置。缩略图和封面分析在受控后台队列执行，人脸位置只辅助本地封面裁切，不修改原图或建立身份分类。
- **订阅**：博主搜索、手动添加、独立的间隔与固定时间计划、手动扫描、头像缓存和扫描记录。选中搜索结果后仍需点击“添加订阅”。
- **设置**：运行参数、分级环境检测、独立下载检测、媒体索引、复制迁移、备份恢复和脱敏诊断。

性能取决于媒体规模、磁盘、图像尺寸和缓存状态；分页与后台处理不意味着任意规模都能瞬间打开。平台登录、限流、页面变化和内容可见性会影响采集结果，增加扫描计划不能保证永不漏抓。

## 首次安装与启动（Windows PowerShell）

当前开发验证环境为 **Python 3.14.2、Node.js 24.13、Vite 6.4.3**。这不是所有 Python、Node 或操作系统版本的兼容矩阵。锁定的 Vite 声明 Node `^18.0.0 || ^20.0.0 || >=22.0.0`，但依赖自身可能有更窄限制，不能据此认为这些版本均已验证。

先安装 Python、Node.js 和 Git，再执行：

```powershell
git clone https://github.com/wiizZ82066/mediasqurrel.git
Set-Location mediasqurrel
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m playwright install chromium
Set-Location frontend
npm ci
Set-Location ..
.\.venv\Scripts\python.exe run.py
```

使用已激活的虚拟环境时，启动命令就是 `python run.py`。微博下载器使用 Playwright Chromium；抖音浏览器逻辑优先尝试系统 Chrome，并提供 Chromium 回退。设置页可分别检测两种浏览器是否实际可启动。浏览器文件存在不等于已通过启动检测，更不等于平台下载可用。

Windows 也可双击项目内的 `start.bat`。它会固定从自身目录启动，优先使用项目的 `.venv`，否则使用 `PATH` 中的 Python；支持透传命令行参数，启动失败会保留窗口供查看原因。

首次启动会构建前端。以后启动会检查 `frontend/src`、`public`、构建配置和锁文件的指纹，以及构建资源完整性；只有源码变化或产物缺失、损坏时才运行 `npm run build`，不会每次安装依赖或无条件重建。拉取代码后，若 Python 依赖或前端锁文件变化，请分别重新安装对应依赖；启动器不会代办安装。

默认打开 `http://127.0.0.1:8642`，服务只绑定本机回环地址。常用选项：

```powershell
python run.py --no-tray       # 不使用托盘，在控制台运行
python run.py --no-browser    # 不自动打开网页
python run.py --port 9000     # 使用另一个本机端口
```

关闭浏览器后，服务、排队下载和订阅扫描仍可继续。退出请使用托盘菜单或控制台 Ctrl+C，程序会停止调度并清理工作子进程。重复启动只有在数据目录、源码位置和启动时的代码指纹均匹配，且前端构建有效时才打开现有实例；检测到旧代码或无法核实的旧实例会提示先从托盘正常退出再重新启动。更新代码后，关闭网页不能代替退出后台服务；服务重新启动后，已打开的网页也需要完整刷新，切换栏目不会重新加载前端代码。同一数据目录不能有两个写入进程。端口被其他程序占用时会提示，不会杀掉占用进程。

目前通知只在打开的网页内显示，关闭网页后没有系统通知。应用退出、电脑关机或休眠期间不能执行扫描；没有自动配置开机启动、系统计划任务或唤醒电脑。

## 数据位置

新源码安装默认使用：

| 内容 | Windows 默认位置 |
| --- | --- |
| 数据库、任务日志、设置与本地登录信息 | `%LOCALAPPDATA%\Media Squirrel\data` |
| 媒体原文件 | `%LOCALAPPDATA%\Media Squirrel\library` |
| 此源码副本的本地路径配置 | 项目中的 `.mediasquirrel.local.json`（Git 忽略） |

媒体文件应放在项目目录之外。设置页显示实际生效位置，以及发现的旧源码版、旧桌面版候选位置；不会自动导入、合并或搬走旧数据。旧桌面版常使用 `app_data`，旧源码版还可能把媒体存到项目目录，不能把换启动方式视为迁移完成。

首次使用、尚未产生数据时，可在启动前创建本地路径配置，填写独立的绝对路径，例如：

```json
{
  "data_dir": "D:\\MediaSquirrelData\\data",
  "library_root": "D:\\MediaSquirrelData\\library"
}
```

已有数据后，请通过设置中的预检与副本流程更换位置，避免只改路径导致旧数据看似消失。高级环境配置包括 `MS_HOME`（基础目录）、`MS_APP_DATA_DIR`（应用数据）、`MS_LIBRARY_DIR`（媒体）、`MS_PATHS_FILE`（本地路径配置文件）和 `MS_PORT`。旧的 `MS_DATA_DIR` 表示包含 `app_data/` 与 `library/` 的便携根目录，并非数据库目录；路径环境变量覆盖本地配置时，界面路径切换会要求先移除覆盖并重启。

媒体原件、`context.md` 和新存档的 `entry.json` 是应保留的源数据；订阅、任务历史、日志与设置也应备份。媒体查询索引、缩略图和封面分析缓存可以重建。新存档目录包含日期、平台和内容 ID；`entry.json` 记录稳定 ID、文件清单和完成状态。旧的 `<作者>/<日期>/`、`context.md`、图片与 Live 图配对仍可建立索引，旧格式会单独标记，不能仅凭一个 `context.md` 推断历史下载完整。新的纯文字微博可以是有效完成存档。

## 四类数据维护

设置中的操作会先生成预检结果，展示源与目标、文件数量、容量、冲突和缺失，再由用户确认执行。

| 场景 | 当前行为 |
| --- | --- |
| **A. 数据库结构升级** | 当前数据库启动时按版本升级，升级前创建一致性备份，迁移使用事务并记录版本。引入旧版数据库可选“旧数据库结构升级副本”，在新目录中升级，不覆盖旧库、不合并两份业务历史。 |
| **B. 已有媒体建立索引** | 只读取已有媒体，在应用数据库中登记媒体根与索引；不复制、移动或改写原媒体。当前配置的默认媒体根会在后台增量扫描；其他旧位置需明确选择。 |
| **C. 换磁盘或媒体位置** | 复制到新目录并校验文件，原目录保留；完成后另行确认下次启动路径。当前进程不会直接换库，退出重启后再次验证并应用映射。 |
| **D. 备份与恢复** | 备份数据库、详细日志和设置；恢复到新的数据目录并验证，再明确选择下次启动使用。媒体原件需另行复制，备份不包含 Cookie、浏览器档案和缓存。 |

维护进度与计划持久保存，可以取消并在条件仍满足时继续。源数据变化、目标冲突、文件缺失或空间不足会要求处理或重新预检，不会删除原目录或覆盖旧数据库。准备副本后若又产生任务、日志、订阅或设置变化，路径切换会拒绝使用过期副本；应重新准备，再及时退出重启。

跨电脑迁移时，需要分别携带应用数据备份和媒体副本，在新电脑恢复并重新建立或确认媒体路径。凭据不会随备份迁移，登录需重新完成。备份仍可能包含私人正文、历史与路径，不能当成可公开分享的诊断包。

## 任务、日志与媒体浏览

任务和详细日志默认永久保留，不按天数或条数自动过期。日志分批写入 SQLite，终态日志压缩归档，页面只按需读取有界窗口。异常断电可能丢失最后尚未提交的一小批日志；排队任务重启后继续调度，原运行任务标记“中断”，可创建关联原任务的重试，不承诺字节级断点续传。

设置页展示任务数量、数据库和归档日志占用、数据盘剩余容量，统计最多缓存 60 秒。低于 512 MiB 会提醒备份或手动清理，不自动删除历史。缩略图使用容量目标与淘汰机制，最近 10 分钟使用的缓存受保护，可能短时超过设置的目标。

媒体时间线优先使用 `context.md` 的发布时间，其次为目录日期、新存档记录的下载时间，均缺失时使用导入时间；界面显示日期来源，日期分组按 Asia/Shanghai。没有默认从 EXIF 推断拍摄日期。列表与正文搜索走持久化索引，原文件变更后通过增量扫描校正。删除文件不会自动删除任务记录，也不会让已确认下载成功的订阅内容自动重下。

## 订阅计划与扫描覆盖

新增订阅首次扫描只建立基线，不自动回溯下载全部历史。间隔计划、每天一个或多个时点、按星期、明确日期、按天／周／月重复可以分别设置；计划包含时区、开始日期、次数或结束日期，并显示下次执行及结果。按月重复沿用起始日，短月份夹到月末；次数计算计划时点，包含错过后被合并的时点。

手动扫描不推迟原计划；同一订阅的重叠触发共用扫描与去重。休眠或停机错过的到期触发会在应用恢复运行后合并补扫，不逐个重放。失败有有限退避重试，扫描结果与下载结果分别记录；发现、入队、下载成功、失败待重试不会混成一个“已见”标记。用户取消的下载不默认自动重试。

微博先从主页资料读取昵称、头像及作品列表入口，再主动分页；访客权限不足时明确提示登录，不把受限响应当成空内容。订阅页可主动打开微博或抖音登录窗口，凭据仅保存在当前数据目录，本地存在不等于平台仍接受。

扫描支持受限分页与重叠回看窗口，可设置最大页数、条目数、超时和回看范围。界面记录覆盖不足及原因；平台限流、置顶内容、页面变化、未公开内容或超过扫描上限仍可能造成遗漏。应结合扫描记录判断覆盖情况，必要时使用明确链接下载。

## 检测与排错

设置页按不同证据分别展示结果：

1. **依赖与脚本**：实际导入依赖及下载脚本、解析脚本语法，并检查浏览器文件；不只看入口文件是否存在。
2. **浏览器环境**：尝试启动浏览器并打开空白页，不访问平台。
3. **登录态**：显示本地是否保存登录信息；保存存在不代表平台仍接受，登录内容不会展示在界面。
4. **真实下载**：填写自己确认的测试链接，再确认联网；输出进入独立诊断目录，不加入正常媒体库。从任务详情查看实际结果。

端口冲突可先检查已有实例，或使用 `--port`。构建提示缺少依赖时，在 `frontend` 执行 `npm ci`。平台验证或登录失败时，按页面提示完成验证，并检查对应任务或扫描记录，不应把重试视为必然恢复。脱敏诊断导出用于排错，分享前仍应自行审阅。

## 开发与扩展

生产式源码运行由 FastAPI 托管前端构建。开发时可在两个终端分别运行：

```powershell
# 终端一，项目根目录，使用已准备的 Python 环境
$env:MS_DEV = '1'
python run.py --reload --no-tray --no-browser

# 终端二
Set-Location frontend
npm run dev
```

开发页面为 `http://127.0.0.1:5173`；如更换后端端口，两个终端应使用相同的 `MS_PORT`。结束开发后移除 `MS_DEV`，恢复正常前端构建检查。

主要模块：`app/task_manager.py`、`task_store.py` 管理任务与日志，`catalog.py`、`library_service.py` 管理媒体索引，`watcher.py`、`scheduling.py` 和 `scanners/` 管理订阅，`maintenance.py`、`path_transition.py` 管理数据维护。前端设计见 [DESIGN.md](DESIGN.md)。

下载脚本由 `scripts_manifest/*.json` 注册。扩展时需同时适配参数校验、进度协议、`entry.json` 完成标记、媒体索引及平台界面，并添加有价值的回归测试；并非添加清单就能保证所有能力自动接入。新增代码文件只在白名单 `.gitignore` 中放行明确路径，不放开媒体目录。

提交前运行 `python .github/scripts/check-repository.py` 并人工审查差异。个人媒体、本地报告、数据库、缓存、浏览器档案、Cookie、密钥和私人路径不得进入 Git。测试使用隔离目录，不能把真实平台测试、受控测试和静态检查混称为同一种验证。
